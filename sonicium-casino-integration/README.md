# Sonicium Entropy × Casino Platform: integration video (English and Bengali)

This is a B2B explainer for a casino-platform audience. It covers:
- what Sonicium Entropy is;
- where it fits in a casino platform's backend;
- the verified API integration, step by step;
- how to judge business value without inflated claims;
- an illustrative ROI calculator;
- a staged path from proof of concept to commercial evaluation.

The film comes in two language versions with identical visuals, each under five minutes. HTML/SVG scenes are rendered frame by frame in headless Chromium and encoded with ffmpeg.

## What the video does and does not claim

- **API details.** Endpoint, auth, parameters, response fields, error codes, plan limits and the signed usage export are all verified against the Sonicium Entropy source. See `sonicium_entropy_api_demo.md` for the files.
- **API key.** No real key appears anywhere. The visible key is the fictional placeholder `YOUR_SONICIUM_API_KEY`, and code reads `SONICIUM_API_KEY` from the environment or a secret manager.
- **Live wagering.** Use with live wagering is shown only as subject to the game's approved outcome-generation design, the applicable regulations and independent testing-laboratory requirements. The film presents a technical evaluation, not an approved game RNG.
- **Business value.** The film does not claim the service increases winnings or revenue, changes the house edge, guarantees profit or proves fairness. The value table uses "measure" placeholders, never invented numbers.
- **ROI scene.** It carries the label **ILLUSTRATIVE SCENARIO — NOT A CUSTOMER FORECAST OR GUARANTEED RETURN**. Its figures are recomputed from the JSON:
  - Monthly cost: $600.
  - First-year cost: $9,200.
  - Cost per million requests: $76.67.
  - Net benefit: $2,800.
  - ROI: ≈ 30.4%.
  - Break-even: ≈ month 5.
- **Plan note.** The scene also points out that 10M requests a month exceeds the Business plan's 2M quota, so an Enterprise agreement would apply. The $500 fee is a sample assumption, not a price.
- **Build check.** `tools/check.mjs` fails the build on:
  - key-shaped strings;
  - literal bearer tokens;
  - unsupported claims that are not negated;
  - Bengali র‍্য spelling errors;
  - subtitle overlap;
  - a video longer than 5 minutes.

## Project structure

```
src/index.html, style.css, animate.js   8 scenes, bilingual (t-en / t-bn), animation engine
src/script.js                          narration for both languages, one cue per sentence
src/timing.en.js, timing.bn.js         generated: scene bounds, cue times, subtitle chunks
src/data.js                            generated from the ROI JSON
tools/build_data.mjs                   ROI JSON → src/data.js (asserts the sample outputs)
tools/timing.mjs --lang en|bn          timing (estimate, or --voice to align to a recording)
tools/make_srt.mjs --lang en|bn        subtitles
tools/make_audio.py --lang en|bn       music, or the voice mix with ducked music (--voice)
tools/make_storyboard.mjs              storyboard + voice-over scripts
tools/check.mjs                        credential, claim, spelling, timing checks
tools/render.mjs --lang en|bn          full render, or --stills t1,t2 for review PNGs
api-demo/                              stdlib Python client + controlled evaluation harness
```

## Build

```bash
node tools/build_data.mjs
for L in en bn; do
  node tools/timing.mjs --lang $L
  node tools/make_srt.mjs --lang $L
  python3 tools/make_audio.py --lang $L
done
node tools/make_storyboard.mjs && node tools/check.mjs
node tools/render.mjs --lang en && node tools/render.mjs --lang bn
```

Dependencies:
- Node 20+ with Playwright and Chromium
- ffmpeg (libx264, AAC)
- Python 3 with numpy

## Adding your voice-over

1. Record each language from `output/voiceover-script-<lang>.txt`, in ElevenLabs or elsewhere. Leave natural pauses between sentences.
   - To stay within 5 minutes, keep each recording under about 4:50.
   - The video runs for the recording plus a 4.5-second tail. `check.mjs` flags anything over 300 s.
2. Save the recordings as `output/voiceover_en.mp3` and `output/voiceover_bn.mp3`, then run for each language:
   ```bash
   L=en   # then L=bn
   node tools/timing.mjs --lang $L --voice output/voiceover_$L.mp3    # aligns all 35 sentences, lists outliers
   node tools/make_srt.mjs --lang $L
   python3 tools/make_audio.py --lang $L --voice output/voiceover_$L.mp3
   ffmpeg -y -i output/voiceover_$L.mp3 -ar 48000 -ac 1 output/sonicium_entropy_casino_voiceover_$L.wav
   node tools/make_storyboard.mjs && node tools/check.mjs
   node tools/render.mjs --lang $L
   ```

Scene lengths, every reveal and the subtitles follow the recording automatically. If the recording's wording differs from `src/script.js`, update the script first, so the sentence count and subtitles match.

## Changing the ROI scenario

Edit `inputs` in `sonicium_entropy_roi_calculator.json`, run `node tools/build_data.mjs`, and re-render. The output tiles, chart and break-even month all follow the inputs.

The expected-output assertion runs only for the brief's sample inputs.
